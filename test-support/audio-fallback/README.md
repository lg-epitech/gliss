# Audio fallback component

`probe.mjs` measures decoding of the fixed synthetic inputs generated by the
`audio-fallback-probe` Rust example. It disables WebCodecs, keeps the server's
CSP, and returns per-file duration, decode time, distortion and native-reference
differences. It creates AudioBuffers without playing them. Guest-to-browser
playback is tested separately by `scripts/test-qemu-audio-fallback.mjs`.

Use the CPU/device isolation and bounded systemd scope in
[development](../../docs/development.md#audio-performance-study). Choose fresh
input and report destinations. Within that scope, these are the payload commands
for the selected component:

```sh
cargo test --locked --offline --release -j1 -p gliss-server --example audio-fallback-probe
GLISS_AUDIO_COMPONENT_ADPCM=1 cargo run --quiet --locked --offline --release -j1 \
  -p gliss-server --example audio-fallback-probe > NEW-INPUT.json
node test-support/audio-fallback/probe.mjs NEW-INPUT.json NEW-REPORT.json
```

Without the ADPCM variable, the generator emits the reset-per-file Ogg variants.
`GLISS_OGG_COMPONENT_ROLLING=1` selects the rolling-packet Ogg experiment.
Those prototypes remain outside the production server. Exact source revisions
and original results for all four rounds are retained in the
[fallback study](../../benchmarks/audio-fallback/README.md).
